# Карантин: эксплуатация

**Относится к:** ТЗ MSP 1.3 §32–§36, §63, §70; руководство аналитика — [ANALYST_GUIDE.md](ANALYST_GUIDE.md)

## Настройка

| Параметр | Назначение |
|---|---|
| `MSP_QUARANTINE_ENCRYPTION_KEY` (или `…_FILE`) | ключ шифрования; не короче 32 символов; без него узел получает `503` и **доставляет** письма |
| `MSP_QUARANTINE_RETENTION_DAYS` | срок хранения (30) |
| `MSP_QUARANTINE_RELEASE_TOKEN_TTL_MINUTES` | жизнь ссылки выпуска (30) |
| `MSP_OBJECT_STORAGE_*` | хранилище объектов; карантин пишет под префикс `quarantine/` |

Ключ шифрования — секрет: в Git, базу, журналы и интерфейс он не попадает. Потеря ключа делает хранимые письма нечитаемыми
(записи остаются, содержимое — нет); храните копию ключа отдельно от хранилища. Смена ключа требует переупаковки: в этом этапе она
не автоматизирована.

## Ежедневно

* «Карантин»: новые письма, причины (`RISK_*`, `ENCRYPTED_UNSCANNABLE`, `MALWARE_*`), версия политики, срок хранения.
* Каждое письмо: безопасный предпросмотр → выпустить / оставить / удалить (удаление — право `quarantine:delete`, администратор ИБ).
* Письма с причиной «вредоносное» или фишинг выпускаются **вдвоём**.
* Тревоги: `QUARANTINE_SPIKE`, `msp_enforcement_quarantine_failopen_total` (карантин был недоступен, письма доставлены).

## Выпуск письма

1. Аналитик нажимает «Запросить выпуск». Для обычных причин запрос сразу считается согласованным.
2. Для серьёзных причин второй человек нажимает «Согласовать» (автор запроса — 403).
3. Узел забирает согласованные выпуски (раз в 3 секунды), получает **одноразовую ссылку**, сверяет контрольную сумму письма и
   подаёт его в Postfix на отдельный слушатель повторной подачи (без фильтра и сканера, только от адреса службы).
4. Узел подтверждает; запись становится `RELEASED`, `delivered_count = 1`. Повторная доставка тем же выпуском невозможна.
5. Письмо с тем же `Message-ID`, уже выпущенное, второй раз в карантин не попадёт.

Сбой повторной подачи оставляет выпуск ожидающим; при следующем опросе узел получит новую ссылку.

## Что делать при проблемах

| Симптом | Действие |
|---|---|
| Узел получает `503` при сдаче письма | не настроен ключ шифрования или хранилище недоступно; письма доставляются (открытый сбой) — настройте и проверьте |
| Выпуск «висит» | служба `gateway-afterqueue` недоступна или слушатель повторной подачи не принимает адрес службы; смотрите журнал Postfix `postfix-reinject` |
| Письмо вернулось в карантин | недопустимо; проверьте, что повторная подача идёт на порт повторной подачи, а не на 25 |
| Нужно удалить письмо насовсем | `quarantine:delete`; содержимое стирается из хранилища, метаданные остаются в аудите |
| Истёк срок | содержимое удаляется, состояние `EXPIRED` |

## Чего здесь нет

Пользовательского портала, ссылок для сотрудников и дайджеста (MSP 1.4). Экспорта исходных писем из консоли нет сознательно.
