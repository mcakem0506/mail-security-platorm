# Резервное копирование и восстановление

Соответствует §32 ТЗ. **Restore drill обязателен до приёмки в production.**

---

## 1. Что копируется

| Объект | Включено | Почему |
|---|:--:|---|
| PostgreSQL (все данные, политики, аудит) | да | авторитетное хранилище |
| Конфигурация (`compose.yml`, nginx) | да | нужна для воспроизведения развёртывания |
| Версии политик | да | часть базы данных |
| Object storage (EML, вложения) | по политике | основной объём; включается `INCLUDE_OBJECT_STORAGE=true` |
| Файлы секретов | **нет** | живут в хранилище секретов и ротируются отдельно (§28) |
| TLS-ключи | **нет** | то же |
| Redis | **нет** | кэш и брокер, не авторитетное хранилище (§32) |

Потеря Redis означает потерю сессий (пользователи войдут заново) и кэша Threat Intelligence
(будет наполнен заново). Данные при этом не теряются.

---

## 2. Снятие копии

```bash
./infrastructure/backup/backup.sh
```

С включением объектного хранилища:

```bash
INCLUDE_OBJECT_STORAGE=true ./infrastructure/backup/backup.sh
```

Скрипт делает больше, чем дамп:

1. снимает дамп PostgreSQL в формате `custom` с `--clean --if-exists`, пригодный для наложения
   на заполненную базу;
2. проверяет, что дамп непустой;
3. **проверяет, что дамп читается** (`pg_restore --list`) — иначе копия считается неудачной;
4. проверяет, что в дампе есть данные таблиц;
5. записывает манифест с размером и составом;
6. удаляет копии старше `BACKUP_RETAIN_DAYS` (по умолчанию 30).

Копия, которую невозможно прочитать, копией не является. Поэтому проверка встроена в процесс
снятия, а не оставлена на момент аварии.

### Расписание

```text
30 2 * * * cd /opt/mail-security-platform && ./infrastructure/backup/backup.sh >> /var/log/msp-backup.log 2>&1
30 3 * * 0 cd /opt/mail-security-platform && INCLUDE_OBJECT_STORAGE=true ./infrastructure/backup/backup.sh >> /var/log/msp-backup.log 2>&1
```

Ежедневно — база и конфигурация, еженедельно — вместе с объектным хранилищем.
Каталог с копиями сам должен попадать в резервное копирование инфраструктуры.

## 3. Restore drill (обязателен)

Проверка восстановимости **без остановки production**: восстановление идёт в отдельную базу.

```bash
./infrastructure/backup/restore.sh /backup/20260928T023000Z
```

Скрипт создаёт временную базу, восстанавливает в неё дамп, проверяет количество таблиц
и наличие событий аудита, затем удаляет временную базу и печатает `RESTORE DRILL PASSED`.

Результат фиксируется в отчёте о приёмке:

| Дата | Метка копии | Результат | Таблиц | События аудита | Выполнил |
|---|---|---|---|---|---|
| | | | | | |

Периодичность: перед приёмкой в production, далее не реже одного раза в квартал,
а также после каждого изменения схемы.

---

## 4. Восстановление production

**Разрушающая операция.** Все данные, записанные после снятия копии, будут потеряны.

```bash
./infrastructure/backup/restore.sh /backup/<метка> --target production
```

Порядок действий скрипта:

1. требует ввести имя базы для подтверждения;
2. останавливает `api` и воркеры, чтобы во время восстановления не было записи;
3. восстанавливает дамп;
4. проверяет полноту схемы;
5. применяет миграции — на случай, если копия старше текущей версии схемы;
6. запускает сервисы.

После восстановления:

- проверить `GET /health/dependencies`;
- проверить, что `alembic current` соответствует ожидаемой версии;
- зафиксировать инцидент восстановления и потерянный интервал данных;
- при необходимости восстановить объектное хранилище из соответствующей копии.

## 5. Целевые показатели

| Показатель | Значение для пилота | Основание |
|---|---|---|
| RPO (допустимая потеря данных) | 24 часа | ежедневная копия |
| RTO (время восстановления) | 1 час | восстановление базы на одном узле |
| RPO для объектного хранилища | 7 дней | еженедельная копия; метаданные сохраняются полностью |

Показатели подлежат согласованию с организацией. При необходимости меньшего RPO — увеличить
частоту копий или настроить потоковую репликацию PostgreSQL.

---

## 6. Проверка целостности копии без восстановления

```bash
docker compose exec -T postgres pg_restore --list < /backup/<метка>/postgres.dump | head -30
```

```bash
cat /backup/<метка>/manifest.txt
```

## 7. Частые ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| `dump verification failed` | повреждённый дамп или нехватка места | проверить свободное место, снять копию заново |
| `restored schema looks incomplete` | восстановление прервано | повторить, проверить логи PostgreSQL |
| `pg_restore` сообщает о предупреждениях | различия владельцев объектов | нормально при `--no-owner`; критичны только ошибки |
| После восстановления пользователи не могут войти | ключ подписи сессий изменился | ожидаемо: сессии не восстанавливаются, требуется повторный вход |
| Вложения недоступны после восстановления базы | объектное хранилище не восстановлено | восстановить из еженедельной копии либо принять потерю содержимого — метаданные сохранены |
