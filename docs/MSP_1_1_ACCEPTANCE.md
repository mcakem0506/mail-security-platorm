# Приёмка MSP 1.1 — основа транспортного шлюза

> **MSP 1.1 IS NOT APPROVED FOR PRODUCTION MX CUTOVER.**
> Этап поставляет основу SMTP-транспорта и плоскость управления. Это не «готовый к боевой почте шлюз».

## Решение

**READY_WITH_WARNINGS** для перехода к MSP 1.2 (лабораторная и теневая эксплуатация). К боевому переключению MX
решение **не** относится.

## Предупреждения и честные отклонения

1. **Предусловие 1.0.4.** На старте этапа гейт готовности (`scripts/gateway_readiness.py`) отвечал `NOT_READY`:
   данных реального потока нет. Этап выполнен на лабораторном стенде, а не на боевой почте.
2. **GAP-003 / GAP-004** переведены в `VALIDATION`, не в `RESOLVED`. Условия §56/§57 выполнены на синтетическом
   корпусе; подтверждение на реальном потоке ожидается.
3. Общий токен узла для агента, синхронизации и сборщика.
4. Архивы 7z/RAR — только оглавление; содержимое не распаковывается.
5. Нет высокой доступности; узлы независимы, общего записываемого хранилища нет.
6. Нагрузочные проверки подтверждают поведение, а не пропускную способность боевой установки.
7. Лабораторные сертификаты выпущены внутренним УЦ без Authority Key Identifier.

## Не реализовано намеренно (ТЗ §74)

Оценка спама, RBL/DNSBL, отказ по SPF, принуждение и подпись DKIM/DMARC, блокировка по репутации и VirusTotal,
пользовательский карантин, автоматическое переключение MX, полная высокая доступность, замена SEG. Даже вердикт
`MALICIOUS` не отклоняет, не удаляет и не задерживает письмо (§58).

## Что нужно до рассмотрения боевого переключения

Подтверждение GAP-003/004 на реальном потоке; гейт готовности `READY`; отдельные токены для компонентов узла;
проверка на оборудовании и сертификатах организации; регламент отката ([GATEWAY_ROLLBACK.md](GATEWAY_ROLLBACK.md));
отдельная приёмка по высокой доступности.
