# Откат политики принуждения

**Относится к:** ТЗ MSP 1.3 §16, §21, §22, §60, §76

Опубликованные версии неизменяемы. Откат **возвращает прежнюю версию** как текущую: узлы получают тот же пакет и ту же
контрольную сумму, что были раньше (например, `v1`), а не новую копию. Это видно на панели «Безопасность»: контрольная сумма узла
совпадает с контрольной суммой откатываемой версии.

## Как откатить

`POST /api/v1/enforcement/controls/{id}/rollback` (право `enforcement:rollback`, только администратор ИБ) с версией
(`to_version`); по умолчанию берётся цель отката, записанная при включении. Состояния контролей в панели приводятся к откатываемой
версии, а откатываемый контроль помечается `ROLLED_BACK`. Если цель — «наблюдение» (`SHADOW`), контроль уходит в наблюдение без
смены версии политики. Событие `enforcement.control_rolled_back` пишет версию и контрольную сумму.

**Ограничение.** Откат невозможен к версии с истёкшим сроком (по умолчанию 7 дней): такую версию публикуют заново как новую
(`MSP_ENFORCEMENT_POLICY_VALID_DAYS`). Пауза (`enforcement:pause`, есть и у администратора платформы) публикует новую версию, в которой
контроль приостановлен.

## Что гарантируется

* после отката узлы принимают решения только по откатываемой версии (проверено: «после отката отказов нет»);
* версия, подписанная чужим ключом или подменённая, не принимается; рабочая копия не затирается;
* при повреждении активной копии узел берёт предыдущую; нет ни одной — безопасный режим;
* откат не удаляет журнал решений: записи остаются с версией, под которой были приняты.
