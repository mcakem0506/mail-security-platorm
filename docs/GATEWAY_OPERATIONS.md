# Эксплуатация шлюза: руководство администратора

**Для кого:** администратор платформы и администратор ИБ, которые поддерживают узлы транспорта
**Относится к:** ТЗ MSP 1.1 §38–§48, §65
**См. также:** [ADMIN_GUIDE.md](ADMIN_GUIDE.md), [GATEWAY_LAB_RUNBOOK.md](GATEWAY_LAB_RUNBOOK.md), [GATEWAY_ROLLBACK.md](GATEWAY_ROLLBACK.md)

> **MSP 1.1 IS NOT APPROVED FOR PRODUCTION MX CUTOVER.** Руководство описывает эксплуатацию лабораторного и
> пилотного узла на отдельном тестовом домене.

---

## 1. Кто что может

| Право | Что даёт | Кому выдано по умолчанию |
|---|---|---|
| `gateway:read` | узлы, сводки, справочник, обзор | наблюдатель ИБ, аналитик, администратор ИБ, администратор платформы |
| `gateway:queue:read` | сводка очереди, список копий писем (без тела) | они же |
| `gateway:tls:read` | сведения о сертификатах | они же |
| `gateway:config:read` | версии конфигурации, маршруты | администратор ИБ, администратор платформы |
| `gateway:config:validate` | проверить новую конфигурацию (ничего не применяет) | администратор ИБ, администратор платформы |
| `gateway:config:activate` | **назначить** конфигурацию узлам | только администратор ИБ |
| `gateway:config:rollback` | вернуться на прежнюю версию | только администратор ИБ |
| `gateway:recipient:sync` | обновить справочник получателей | только администратор ИБ |
| `gateway:node:drain` | слить узел / вернуть в работу | администратор ИБ, администратор платформы |
| `gateway:queue:admin` | повторить доставку | администратор ИБ, администратор платформы |

Эксплуатация узлов (слив, повтор доставки) и решение о том, **кого принимает граница организации**
(конфигурация, справочник), разделены намеренно: у администратора платформы нет права применять
конфигурацию. Содержимого писем ему это тоже не открывает.

Все изменяющие действия пишутся в журнал аудита отдельными событиями: `transport.config_validated`,
`transport.config_activated`, `transport.config_rolled_back`, `transport.node_drain`, `transport.node_resume`,
`transport.node_flush`, `transport.recipients_sync`, `transport.queue_viewed`. Отказы (в том числе отвергнутую
конфигурацию и отказ справочника) пишутся так же, с исходом `rejected`.

## 2. Консоль

Раздел **«Транспорт почты» → «Шлюз (Gateway)»**, вкладки:

| Вкладка | Что видно |
|---|---|
| Обзор | тревоги (отдельно «не проверяется»), сводка узлов и очереди, состояние справочника, сертификаты |
| Очередь и письма | копии писем, снятые шлюзом (метаданные; фильтр по направлению) |
| Узлы | состояние, последний сигнал, версия конфигурации, давление, проверки (Exchange, открытый релей, дрейф, сборщик), кнопки «Слить», «Повторить доставку» |
| Маршруты | действующие маршруты и принимаемые домены |
| Получатели | возраст и состояние справочника, форма загрузки |
| TLS | сертификаты: назначение, срок, состояние |
| Конфигурация | история версий; проверка новой; «Применить», «Вернуться» |

На каждой вкладке виден баннер **MSP 1.1 IS NOT APPROVED FOR PRODUCTION MX CUTOVER**.

«Нет данных» не рисуется как «хорошо»: узел без сигнала — «не отвечает», проба, которая не выполняется, —
«не проверялось», справочник без загрузки — «приём закрыт».

## 3. Подключение узла к панели

На панели (`.env`; значения секретов — в файлах, не в Git):

| Настройка | Назначение |
|---|---|
| `MSP_GATEWAY_INGEST_TOKEN` / `MSP_GATEWAY_INGEST_TOKEN_FILE` | общий токен узлов; **не короче 32 символов**. Пока не задан, точки приёма от узлов закрыты ответом `503` |
| `MSP_GATEWAY_NODE_STALE_SECONDS` | через сколько секунд молчания узел считается недоступным (180) |
| `MSP_GATEWAY_RECIPIENTS_FRESH_SECONDS`, `…_GRACE_SECONDS` | пороги свежести справочника (3600 и 7200) |
| `MSP_GATEWAY_QUEUE_WARN_MESSAGES`, `…_CRITICAL_MESSAGES`, `MSP_GATEWAY_OLDEST_WARN_SECONDS`, `…_CRITICAL_SECONDS`, `MSP_GATEWAY_COLLECTOR_STALE_SECONDS`, `MSP_GATEWAY_SHADOW_PENDING_WARN_SECONDS` | пороги тревог панели |

На узле (переменные окружения контейнера):

| Переменная | Назначение |
|---|---|
| `MSP_PANEL_URL` | адрес API узлов, например `https://msp.corp.example/api/v1/gateway-agent` |
| `MSP_PANEL_TOKEN_FILE` | файл с токеном (читают синхронизация, агент и сборщик) |
| `MSP_SYNC_INTERVAL` | период опроса панели, секунд (30) |
| `MSP_INGEST_URL`, `MSP_INGEST_TOKEN_FILE` | адрес приёма копий и токен — если сборщик встроен в контейнер узла |
| `MSP_ROLE` | роль узла в панели: `INBOUND`, `OUTBOUND`, `BOTH`, `LAB` |
| `MSP_AGENT` | `0` отключает агент (по умолчанию включён) |
| `MSP_METRICS_PORT` | порт метрик (9100) |
| `MSP_RECIPIENT_GATE` | `1` включает закрытие приёма при безнадёжно устаревшем справочнике |
| `MSP_RECIPIENTS_FRESH_SECONDS`, `MSP_RECIPIENTS_GRACE_SECONDS` | пороги свежести на узле |
| `MSP_PROBE_EXCHANGE`, `MSP_PROBE_CA`, `MSP_PROBE_RECIPIENT`, `MSP_PROBE_REQUIRE_TLS`, `MSP_PROBE_SELFTEST`, `MSP_PROBE_RELAY_PORT`, `MSP_PROBE_INTERVAL` | пробы ([GATEWAY_TLS.md](GATEWAY_TLS.md)) |
| `MSP_CERT_FILES` | `назначение=путь` через запятую — файлы **сертификатов** для отслеживания срока |
| `MSP_COLLECTOR_STATUS` | путь отчёта сборщика, который читает агент |

**Токен — общий секрет узла.** Он даёт право получать назначенную узлу конфигурацию, передавать события и
копии писем. Хранить его как любой секрет (смонтированный файл, права на чтение только процессам узла), менять
при подозрении на утечку (поменять на панели и на узлах). Раздельные токены для агента, синхронизации и
сборщика — известное ограничение этапа ([GATEWAY_SECURITY_MODEL.md](GATEWAY_SECURITY_MODEL.md)).

## 4. Метрики узла

Агент отдаёт `/metrics` (текстовый формат Prometheus) и `/healthz` на порту 9100; порт открывать только во
внутренней сети мониторинга. Правила тревог — в `infrastructure/monitoring/alerts.yml` (группа `msp-gateway`).

| Метрика | Смысл |
|---|---|
| `msp_gateway_smtp_connections_total{direction}` | соединения |
| `msp_gateway_messages_received_total{direction}` | принятые в очередь письма |
| `msp_gateway_messages_rejected_total{direction,class}` | отказы на SMTP (`4xx`, `5xx`) |
| `msp_gateway_messages_deferred_total{direction}` | отложенные попытки доставки |
| `msp_gateway_messages_delivered_total{direction}` | доставленные письма |
| `msp_gateway_delivery_failures_total{direction,class}` | неудачные доставки, включая отказы получателя с переходом на запасную цель |
| `msp_gateway_delivery_delay_seconds` | гистограмма задержки доставки |
| `msp_gateway_queue_messages{queue}`, `msp_gateway_queue_bytes`, `msp_gateway_oldest_message_seconds` | очередь |
| `msp_gateway_disk_free_bytes`, `msp_gateway_pressure_state{state}` | диск и давление |
| `msp_gateway_shadow_delivery_total`, `msp_gateway_shadow_failures_total` | копии, переданные на анализ, и сбои |
| `msp_gateway_recipient_map_age_seconds` | возраст справочника |
| `msp_gateway_config_info{version,checksum,role}` | какая конфигурация применена |
| `msp_gateway_node_up` | агент работает |
| `msp_gateway_exchange_probe_ok{target,layer}` | проба Exchange по уровням (1/0; нет записи — не проверялась) |
| `msp_gateway_open_relay_selftest_ok` | самопроверка открытого релея (1 — отказ, 0 — принял бы) |
| `msp_gateway_certificate_expiry_seconds{usage}` | секунд до окончания сертификата |
| `msp_gateway_config_drift` | 1 — файлы расходятся с принятым описанием |
| `msp_gateway_shadow_collector_report_age_seconds`, `msp_gateway_shadow_pending_seconds` | сборщик копий |

Метки метрик — только из закрытых наборов (направление, класс кода, состояние). Адресов, имён хостов
клиентов, идентификаторов писем и текстов ответов в метках нет: иначе любой, кто может подключиться к порту 25,
раздувал бы память агента.

## 5. Тревоги и что с ними делать

Панель вычисляет тревоги из состояния (`GET /api/v1/gateway/alerts`); тревога исчезает сама, когда условие
пропало.

| Код | Уровень | Что значит | Что делать |
|---|---|---|---|
| `GATEWAY_NODE_DOWN` | критично | узел давно не присылал сигналов; очередь и состояние неизвестны | проверить контейнер и сеть до панели; почту Postfix мог продолжать принимать |
| `QUEUE_GROWTH` | внимание / критично | в очереди больше 1000 / 5000 писем | проверить Exchange (проба), при необходимости «Повторить доставку» |
| `OLDEST_MESSAGE_TOO_OLD` | внимание / критично | письмо ждёт дольше 30 мин / 2 ч | то же; смотреть журнал причин отложенной доставки |
| `EXCHANGE_UNAVAILABLE` | критично | проба упала; в описании назван **уровень** (`NETWORK`, `TLS`, `SMTP`, `DELIVERY`) | идти на названный уровень; письма копятся, не теряются |
| `DISK_PRESSURE` | внимание / критично | давление или критическое давление | [GATEWAY_BACKPRESSURE.md](GATEWAY_BACKPRESSURE.md) |
| `RECIPIENT_MAP_STALE` | внимание / критично | справочник устарел (в пределах допуска / безнадёжно) | загрузить свежую выгрузку |
| `TLS_CERT_EXPIRING` | внимание / критично | сертификат истекает через менее 30 дней / истёк | заменить сертификат |
| `SHADOW_COLLECTOR_UNAVAILABLE`, `SHADOW_COLLECTOR_BACKLOG` | внимание | потеряно наблюдение за новыми письмами; почта идёт | [GATEWAY_SHADOW_ANALYSIS.md](GATEWAY_SHADOW_ANALYSIS.md), раздел 6 |
| `CONFIG_DRIFT` | критично | конфигурацию на узле изменили вне панели | выяснить, кто; применить назначенную версию заново |
| `OPEN_RELAY_SELFTEST_FAILED` | **критично** | недоверенный источник смог адресовать внешнего получателя | **немедленно слить узел**, разобраться, не возвращать до исправления |
| `NO_NODES` | внимание | ни один узел не присылал сигналов | подключить узел |
| `EXCHANGE_NOT_PROBED`, `OPEN_RELAY_NOT_PROBED` | к сведению | проба не настроена: это слепое пятно, а не «всё хорошо» | настроить пробу |

## 6. Повседневные действия

**Обновить справочник получателей** — [GATEWAY_RECIPIENT_VALIDATION.md](GATEWAY_RECIPIENT_VALIDATION.md).

**Изменить конфигурацию.** Консоль → «Конфигурация»: вставить описание топологии (JSON) → «Проверить». Проверка
ничего не применяет и возвращает причины без значений. Версия, прошедшая проверку, получает статус
«проверена»; **«Применить»** (с подтверждением) назначает её узлам; узел применит при ближайшем опросе, проверит
сам и сообщит итог (`last_apply` на вкладке «Узлы»). Узел сам откатывается на прежнюю конфигурацию, если новая не
запустилась или не прошла проверку здоровья.

**Вернуть прежнюю версию.** «Вернуться» у версии со статусом «заменена» или «откатана»
([GATEWAY_ROLLBACK.md](GATEWAY_ROLLBACK.md)).

**Команды на узле** (под root в контейнере):

```bash
python3 -m msp_gateway.node status          # применённая версия и контрольные суммы (в том числе фактическая на диске)
python3 -m msp_gateway.node drain status    # включён ли слив; on / off — включить / выключить
python3 -m msp_gateway.node gate-refresh    # пересчитать свежесть справочника и открыть/закрыть приём получателей
python3 -m msp_gateway.node sync --once     # однократный опрос панели
postqueue -p                                # очередь (Postfix)
```

---

## 7. Чего панель не делает

Не удаляет письма из очереди; не меняет DNS и MX; не управляет Exchange; не перехватывает и не изменяет
письма по результатам анализа. Это сделано намеренно и вынесено за пределы этапа.
