# Золотой корпус

ТЗ 1.0.3 §5, §58. Что лежит в датасете, как он устроен и чего в нём нет никогда.

имитаций, 20 вложений, 20 состязательных.

## Чего в корпусе нет никогда

ТЗ 1.0.3 §5.1 запрещает прямо, и это соблюдается конструктивно: корпус **генерируется кодом**
(`packages/detection-eval/msp_detection_eval/corpus.py`), а не собирается из реальной почты.

| Запрещено | Как исключено |
|---|---|
| живое вредоносное ПО | «исполняемые» вложения — заголовок PE и несколько байт, ничего исполняемого |
| персональные данные без политики | все адреса в доменах `.test` и `.example`, имена вымышленные |
| реальные учётные данные | пароли и ключи не фигурируют; «зашифрованный архив» — выставленный бит, без шифрования |
| секреты организации | корпус не содержит ничего, что не написано в самом генераторе |

Поле `pii_status: NONE` и `approval_status: APPROVED` хранятся в датасете и проверяются при
загрузке.

## Структура кейса

```python
EvaluationCase(
    id="DOC-001",
    category=DatasetCategory.MALICIOUS_ATTACHMENT,
    expected_classification=RiskLevel.HIGH_RISK,
    expected_rules=["ATT-040"],  # должны сработать
    forbidden_rules=[],  # не должны сработать ни при каких условиях
    scenarios=["THR-ATT-003"],  # связь с каталогом угроз
    known_gap="",  # зарегистрированный пробел, если применимо
    requires_enrichment=False,  # нужны ли внешние обращения
    notes="Удалённый шаблон загружается при открытии; макросов в документе нет.",
)
```

Три поля делают кейс проверкой, а не декорацией:

- **`expected_rules`** — иначе кейс проходит «случайно», по другому правилу. Так и была найдена
  слабость корпуса: BEC-кейсы проходили за счёт правил имитации.
- **`forbidden_rules`** — противоположное требование. Кейс `DOC-010` (внутренний документ со
  ссылкой на корпоративный портал) запрещает ATT-040…ATT-043: без него три кейса про опасные
  документы «прошли бы» у правила, которое просто не доверяет любому `.docx`.
- **`known_gap`** — ссылка в [реестр пробелов](DETECTION_GAPS.md). Провал такого кейса гейт
  превращает в предупреждение.

## Парность кейсов

Для каждого опасного приёма в корпусе есть легитимный двойник, отличающийся ровно тем
признаком, который должен решать:

| Атака | Легитимный двойник |
|---|---|
| документ с удалённым шаблоном | внутренний документ со ссылкой на портал |
| смена реквизитов от подрядчика | обычная переписка с тем же подрядчиком |
| имитация отображаемого имени | сотрудник с двумя рабочими ящиками |
| название отдела в имени отправителя | подрядчик, у которого отдел называется так же |
| QR-код с призывом отсканировать | квадратный логотип в подписи |

Две последние пары добавлены после того, как оценка нашла на них 10 ложных срабатываний.

## Версионирование

- **Версия датасета** меняется при любом изменении состава кейсов.
- **Контрольная сумма** считается по утверждениям кейсов (id, категория, ожидаемый вердикт,
  ожидаемые и запрещённые правила), а не по сгенерированным письмам: изменение формулировки в
  `notes` не делает датасет другим, а изменение ожидания — делает.
- **Исторические версии неизменяемы.** `Dataset.write()` отказывается перезаписать файл, в
  котором лежит другая версия: иначе сравнение с базовой линией сравнивало бы разные датасеты,
  думая, что сравнивает одинаковые.
- **`changelog`** внутри датасета описывает, что и почему изменилось.

## Экспорт

```bash
python scripts/export_corpus.py --out /tmp/corpus
```

Выгружает `.eml` всех кейсов и сводный `index.json`. Используется для ручной проверки, для
прогона через сторонние средства защиты и для сравнения с результатами шлюза. В CI эта выгрузка
выполняется в задаче `acceptance-snapshot` — чтобы ломающая её ошибка нашлась до того, как
выгрузка понадобится.

## Как добавлять кейсы

1. Писать на русском языке и в тех формулировках, которые встречаются в деловой переписке.
   Кейс, звучащий как учебный пример, проверяет умение ловить учебные примеры.
2. Указывать `expected_rules`, иначе кейс не проверяет то, что должен.
3. Добавлять легитимного двойника. Без него неизвестно, различает платформа признак или просто
   не доверяет формату.
4. Прогнать `--gate` и, если метрики изменились осознанно, обновить базовую линию тем же
   коммитом.
