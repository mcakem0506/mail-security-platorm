# Семантика действий SMTP

**Относится к:** ТЗ MSP 1.3 §10–§15, §25, §53, §54, §56, §57, §67–§69

## Основное правило

`4xx` — временный отказ (`TEMPFAIL`), `5xx` — постоянный (`REJECT`). Постоянный отказ допустим **только в исходной сессии SMTP**,
до ответа `250`. После `250` письмо принято и находится в очереди Postfix; допустимы лишь удержание, карантин, отложенная
доставка и разбор аналитиком. Послеочередной шлюз не умеет отвечать `5xx` (код проверяется тестом
`tests/enforcement/test_quarantine_e2e.py::…never_sends_a_permanent_error`): отказ после приёма породил бы уведомление о недоставке
отправителю, а адрес отправителя часто подделан (backscatter).

## Ответы

| Решение | Когда | Ответ |
|---|---|---|
| `REJECT` | до очереди, контроль в `CANARY`/`PILOT`, все получатели в области | `554 5.7.1 Message rejected by local policy` |
| `TEMPFAIL` | до очереди (`TEMPFAIL_ABUSE`) или исходящий путь с подозрением на взлом учётной записи | `451 4.7.1 Temporary local policy deferral, try again later` |
| `QUARANTINE` | после очереди, полный анализ MSP | `250` фильтра; письмо в карантине |
| `HOLD` | после очереди, исходящее вредоносное | `451` фильтра: письмо в очереди Postfix; по истечении удержания — управляемый карантин |
| `BYPASS`, `ALLOW`, `NO_DECISION` | всё прочее | письмо идёт дальше |

Код `554` и расширенный `5.7.1` добавляет Milter Rspamd; службе принуждения принадлежит только текст. Текст общий и **не содержит**
внутренней оценки, идентификаторов правил, секретов RBL, защищённых идентификаторов, топологии и имён провайдеров TI (§53); это
проверяют тесты узла и живой стенд.

## Режимы сбоя (§14, §15)

* Таймаут решения до очереди ограничен (`hard_timeout_ms` ≤ 5000; по умолчанию 1500; сторона Rspamd — не больше 3 с).
* `FAIL_OPEN` — по умолчанию для спама, репутации, вредоносного (с тревогой): при ошибке, тайм-ауте или недоступной службе письмо идёт
  дальше. `FAIL_TEMPFAIL` — только для контроля злоупотребления (после проверки).
* Режима «постоянный отказ при внутренней ошибке» **не существует**; тест перебирает все контроли и режимы.
* Недоступны панель, база, внешние сервисы, консоль — синхронный путь не меняется (кэш политики, §49). Недоступен сканер —
  `milter_default_action=accept`, письмо идёт без проверки ([RSPAMD_ARCHITECTURE.md](RSPAMD_ARCHITECTURE.md)).

## Несколько получателей (§68)

Безопасное правило: **разрушительное действие только если все получатели письма в области контроля**. Иначе письмо проходит, а
предложение записывается. Разделение письма по получателям не используется. Служебный получатель транспорта
(копия для теневого анализа) получателем не считается.

## Повторы (§69)

Область канарейки считается по хэшу адреса получателя — детерминированно; повтор того же письма даёт то же решение.
Решение хранит ссылку на предыдущую попытку (`previous_attempt`) и версию политики.

## Порядок проверки и подписи (§56–§58)

Входящее: получение → аутентификация и оценка (Rspamd) → решение → очередь → (после очереди) полный анализ → доставка или
карантин. Исходящее: доверенный приём → анализ/политика → подпись DKIM → доставка; после подписи содержимое не меняется.
Карантин и выпуск сохраняют исходное письмо байт в байт (проверяется контрольной суммой); повторная подача добавляет только
транспортные заголовки, которые подпись DKIM не охватывает. Принуждение использует только доверенные свидетельства шлюза;
`Authentication-Results` и `X-Spam*` из письма — недоверенные (§57).

## Исходящая почта (§55)

Направление определяется слушателем Postfix (символ `MSP_DIRECTION_*` в записи сканера), а не адресом в `From`. Контроли входящего
пути (`SPAM_REJECT`, `DMARC_REJECT`, `RBL_REJECT`, `MALWARE_REJECT`, `PHISHING_REJECT`, `QUARANTINE`) исходящую почту не затрагивают:
решение помечается `OUTBOUND_NOT_IN_SCOPE`, действие — только наблюдение. Действует лишь `OUTBOUND_BLOCK` (по умолчанию в наблюдении):
удержание вредоносного и временный отказ при подозрении на взлом учётной записи. Постоянный внешний отказ исходящей почты требует
отдельной приёмки. Подпись DKIM ставится после решения, и подписанное содержимое после этого не меняется.
