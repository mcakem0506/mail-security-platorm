# Проверка подписей DKIM

**Относится к:** ТЗ MSP 1.2 §9, §38; RFC 6376
**Код:** `msp_antispam/auth.py` (`dkim_evidence`); проверки — `tests/spam/test_dkim.py`, `tests/unit/test_antispam_auth.py`

Подписывает в проверках независимая реализация (dkimpy), проверяет Rspamd: совпадение результата не может быть
следствием общей ошибки.

## Нормализация

Результат письма: `PASS`, `FAIL`, `NONE`, `TEMPERROR`, `PERMERROR`. По каждой подписи сохраняются домен (`d=`), селектор, результат,
выравнивание с доменом из From, состояние ключа (`VERIFIED`, `SIGNATURE_MISMATCH`, `DNS_ERROR`, `KEY_INVALID_OR_MISSING`,
`UNSUPPORTED_OR_WEAK`) и причина.

* **Несколько подписей.** Итог — по лучшей: одна неудачная не отменяет корректную выровненную. Подпись чужого домена
  без выравнивания учитывается как свидетельство, но не как `aligned`.
* **Слабая или неподдерживаемая подпись** (алгоритм, короткий ключ) — отдельное свидетельство `PERMERROR` с признаком
  `unsupported_or_weak`, не `PASS`.
* **Сбой DNS** — `TEMPERROR`, а не `FAIL`.

## Матрица проверок (настоящий Rspamd)

корректная подпись; изменённое тело; изменённый подписанный заголовок; нет ключа в DNS; ключ под другим селектором;
сбой DNS (SERVFAIL); две подписи (своя и чужая); одна нерабочая и одна корректная выровненная; подпись другого домена
(не выровнена); испорченный заголовок подписи; ключ 1024 бита; `rsa-sha1`. Во всех случаях письмо доставляется.

## Наблюдения за установленной версией

* Недопустимые символы *внутри* значения `b=` Rspamd пропускает при разборе base64, поэтому такая порча подпись не
  ломает; ломают её синтаксические ошибки заголовка (пустой алгоритм) и изменение содержимого.
* Ключи короче 1024 бит в проверках стенда не создаются (библиотека подписи отказывается); решение о допустимости
  1024-битного ключа остаётся за политикой организации.
