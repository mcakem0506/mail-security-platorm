# Лицензии и допуск провайдеров репутации

**Относится к:** ТЗ MSP 1.2 §14, §15, §31, §34
**Код:** `msp_antispam/providers.py`, `apps/api/msp_api/services/antispam.py`; проверки — `tests/e2e/test_antispam_e2e.py::TestProviders`, `tests/spam/test_rbl.py`

Публичные списки DNSBL часто бесплатны только для некоммерческого использования. Включать их в корпоративной
эксплуатации без проверки лицензии нельзя, поэтому провайдер без одобрения получает статус
`DISABLED_BY_POLICY`, сколько бы раз его ни «включили» флагом.

## Режимы лицензии

| Режим | Требует допуска |
|---|---|
| `PUBLIC_NONCOMMERCIAL` | да, с областью применения |
| `COMMERCIAL_LICENSED` | да, с областью применения и сроком |
| `SELF_HOSTED` (зеркало или зона организации) | нет внешней лицензии, четыре глаза остаются |
| `LAB_ZONE` (зона стенда) | нет; к реальной почте не применяется |

## Допуск

В записи провайдера хранятся: `license_approved`, `approved_by`, `approved_at`, `usage_scope`, `expires_at`. Срок истёк —
статус `LICENSE_EXPIRED`, провайдер из конфигурации сканера исчезает.

Порядок, четыре глаза (ТЗ §34):

1. администратор ИБ **заводит** провайдера: всегда выключен, состояние `DRAFT`, создать сразу включённым нельзя;
2. он же **запрашивает включение**, указывая область применения лицензии (`request-activation`);
3. **другой** человек с правом `reputation:provider:manage` **одобряет** (`approve`); одобрение собственного запроса
   отклоняется с записью в аудит (`outcome=denied`);
4. сканер получает провайдера при следующей синхронизации (по умолчанию в течение 30 секунд); `suspend` убирает его так же.

Каждый шаг пишет событие аудита: `antispam.provider_created`, `…_activation_requested`, `…_approved`, `…_rejected`,
`…_suspended`.

## Приватность

Запрос к внешней зоне раскрывает её оператору, о каком адресе или домене спрашивали. Поэтому у провайдера есть класс
приватности (`EXTERNAL_DNS` / `INTERNAL`), а типы запросов включаются по одному
([REPUTATION_PROVIDERS.md](REPUTATION_PROVIDERS.md)). Решение «разрешено ли раскрывать эти данные внешнему оператору» принимает
организация при одобрении, и оно записывается в область применения.

## CI и лаборатория

CI не зависит от публичных списков: зона `rbl.lab.test` обслуживается управляемым DNS стенда. Публичный провайдер в
тестах — вымышленная зона без обращения к Интернету; проверяется, что до одобрения запросов к ней нет вообще.
