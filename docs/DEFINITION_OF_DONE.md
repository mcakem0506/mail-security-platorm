# Definition of Done

Задача считается выполненной, только если применимые пункты закрыты (AGENTS.md §21). «Код написан» ничего не доказывает: этап
считается готовым по тестам и доказательствам, а не по объёму изменений.

| Пункт | Как проверяется в репозитории |
|---|---|
| Реализация | код + повторное использование существующих механизмов, без параллельных |
| Автотесты | `tests/unit`, `tests/e2e`, `tests/integration`; для дефектов — регрессионный тест, написанный до исправления |
| Тесты безопасности | `tests/security`, проверки прав/четырёх глаз/подделок в `tests/e2e/test_*_e2e.py` и живых наборах |
| Миграции | Alembic; для нетривиальных: `upgrade → downgrade → upgrade → alembic check` |
| Линт и типы | `ruff check`, `ruff format --check`, `mypy packages apps/api/msp_api apps/worker providers`, `tsc` консоли |
| Проверка конфигурации | типизированные модели, проверка узла, нативные проверки Postfix/Rspamd, эталон отрисованной конфигурации |
| Документация | в том же изменении; руководства сотрудника, аналитика, администратора |
| Наблюдаемость | метрики и тревоги; тест `test_alerts.py` следит, чтобы тревоги ссылались на существующие метрики |
| Откат | описан и проверен (конфигурации, политики принуждения, MX) |
| Доказательства приёмки | `docs/MSP_*_ACCEPTANCE.md`: что проверено, чем, и чего нет (`NOT_TESTED`/`UNKNOWN` вместо выдуманного успеха) |

Критические проверки (принуждение, надёжность очереди, открытый релей, TLS, политика, карантин, откат) детерминированы:
повторов до зелёного в CI нет (`tests/unit/test_ci_no_retry.py`).
