# Аварийный сценарий ложного срабатывания

**Относится к:** ТЗ MSP 1.3 §37, §38, §45, §46, §65

Ложное срабатывание принуждения — это законное письмо, которое отклонено или попало в карантин. Критическое — когда это письмо важно
(платёж, юридическое, руководство) или таких писем много.

## Автоматически

Аналитик помечает решение «критическое ложное» (`POST /enforcement/decisions/{id}/review`, `critical=true`). Платформа **сразу**:
1. приостанавливает затронутый контроль (новая подписанная версия политики); если ключ подписи недоступен — включает общий выключатель;
2. открывает инцидент (`OPEN`) с версией политики и затронутым письмом;
3. пишет события аудита; поднимает тревогу `CRITICAL_FALSE_POSITIVE`.

## Шаги инцидента

`OPEN → CONTAINED → ROOT_CAUSE_FOUND → REGRESSION_ADDED → CLOSED` — этапы нельзя пропускать (409).
1. **Сдерживание.** Контроль приостановлен или включён выключатель; убедитесь, что узлы получили версию (панель «Безопасность»).
2. **Найти затронутые письма.** Журнал решений с фильтром по контролю и версии политики; письма в карантине — раздел «Карантин».
3. **Выпустить, что возможно.** Выпуск из карантина идёт обычным порядком ([QUARANTINE_OPERATIONS.md](QUARANTINE_OPERATIONS.md)); отказанные в
   исходной сессии письма отправитель увидит как ошибку 5xx — их можно запросить повторно.
4. **Причина** (≥ 20 символов): какой порог, символ, список или исключение дали ошибку.
5. **Регрессионный случай** — ссылка на добавленный тест или пример корпуса. Без него инцидент не закрывается.
6. **Закрытие.** Только после него контроль можно снова запрашивать; включение по-прежнему вдвоём и по готовности.

## Чего делать нельзя

**Бессрочный список разрешённых не создаётся** (§38). Нужно временное исключение — оно срочное, с владельцем и причиной
([ENFORCEMENT_EXCEPTIONS.md](ENFORCEMENT_EXCEPTIONS.md)). Пока по контролю есть незакрытый инцидент, запрос на включение отклоняется (409), а готовность — `NOT_READY` с
причиной `SYSTEMIC_FP_UNRESOLVED`.

## Метрики безопасности

`RejectSafety`: просмотрено, верно, ложных, критических, доля ложных (`null` без знаменателя), верхняя граница, окно выборки,
готовность к канарейке и пилоту. Недостаточная выборка (< 100 по умолчанию) — `NOT_READY`.
