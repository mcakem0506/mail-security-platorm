# Внутренний карантин

**Относится к:** ТЗ MSP 1.3 §32–§36, §58, §63
**Код:** `apps/api/msp_api/services/quarantine.py`, `routers/enforcement.py`, `msp_enforcement/afterqueue.py`

> Пользовательского портала карантина, ссылок выпуска для сотрудников и дайджеста в этом этапе нет (MSP 1.4).

## Запись и хранение

`QuarantineItem`: письмо (`transport_message_id`, `internet_message_id`), ссылка на содержимое, решение (`decision_ref` =
версия политики и контроль), состояние, срок хранения, исходный маршрут, кто и когда выпустил.

* **Содержимое.** Исходное письмо шифруется AES-256-GCM (ключ из хранилища секретов, `MSP_QUARANTINE_ENCRYPTION_KEY`, не короче
  32 символов; идентификатор записи входит в аутентифицируемые данные) и лежит под отдельным префиксом хранилища объектов
  `quarantine/`. Контрольная сумма исходного письма хранится в записи и проверяется при каждом чтении; повреждённое или
  подменённое письмо не отдаётся. Исходное письмо неизменяемо.
* **Доступ.** Только через точки карантина (`quarantine:read`, `quarantine:release`, `quarantine:delete`); публичных ссылок нет;
  ни одна другая точка API ключ карантина не принимает. Просмотр, выпуск и удаление пишутся в аудит.
* **Без ключа шифрования** узел получает `503` и **доставляет письмо** (открытый сбой): потеря письма из-за недоступности
  хранилища исключена.
* **Срок хранения** — `MSP_QUARANTINE_RETENTION_DAYS` (30); по истечении содержимое удаляется, запись остаётся со статусом
  `EXPIRED`.

Состояния: `QUARANTINED → RELEASE_PENDING → RELEASED`, а также `DELETED`, `EXPIRED`, `ERROR`.

## HOLD и QUARANTINE (§36)

`HOLD` — краткое операционное состояние узла: письмо остаётся в очереди Postfix (ответ фильтра `451`) на ограниченное время
(по умолчанию 30 минут), затем становится управляемым карантином. `QUARANTINE` — состояние приложения: хранится, ищется,
имеет владельца, срок и аудит.

## Выпуск (§34, §35)

```text
просмотр → запрос выпуска → согласование (если нужно) → одноразовая ссылка → доверенная повторная подача → «доставлено один раз»
```

* Согласование вторым человеком требуется, если причины включают вредоносное (`MALWARE*`), `RISK_MALICIOUS` или фишинг.
* Ссылку выпуска выдаёт панель узлу при опросе: в базе хранится только её хэш, срок короткий (30 минут), прежняя ссылка при
  выдаче новой недействительна, **использованная ссылка не принимается повторно**, чужая или просроченная — отказ (403/410).
* Узел забирает письмо по ссылке, сверяет контрольную сумму, подаёт его на слушатель повторной подачи (без фильтра и сканера) и
  подтверждает. Сбой подачи оставляет выпуск ожидающим (ссылка гасится, при следующем опросе выдаётся новая).
* **Защита от петли.** Повторная подача не проходит через фильтр, а панель не карантинит письмо с тем же `Message-ID`, уже выпущенное
  ранее (ответ узлу — «уже выпущено», письмо доставляется). Защита не опирается на заголовок, который мог бы подделать отправитель.
* Выпуск не меняет содержимое, подписанное DKIM.

Безопасный просмотр: выбранные заголовки, обрезанный текст без HTML, список вложений; ссылки обезврежены (`hxxp`).
