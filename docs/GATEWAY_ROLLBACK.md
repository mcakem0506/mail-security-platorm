# Откат: конфигурация, справочник, узел, этап

**Относится к:** ТЗ MSP 1.1 §69 (откат), §61
**Дополняет:** [GATEWAY_OPERATIONS.md](GATEWAY_OPERATIONS.md), [../deployment/exchange/rollback-plan.md](../deployment/exchange/rollback-plan.md)

> **MSP 1.1 IS NOT APPROVED FOR PRODUCTION MX CUTOVER.**
> Платформа не меняет DNS/MX и не меняет Exchange сама. Поэтому «откат» этапа — это отсутствие действий в
> боевой почте: пока MX не переключён, шлюз в боевом потоке не стоит.

---

## 1. Уровни отката

| Что откатываем | Как | Кто | Эффект на почту |
|---|---|---|---|
| Неудачная новая конфигурация при применении | **автоматически**: узел не прошёл проверку здоровья → возврат на прежнюю версию, статус версии `ROLLED_BACK` | узел | приём не прерывается дольше перезагрузки Postfix |
| Конфигурация, оказавшаяся плохой после применения | «Вернуться» у прежней версии (`POST /api/v1/gateway/config/rollback`, право `gateway:config:rollback`) | администратор ИБ | то же, что при применении новой версии |
| Справочник получателей | выгрузка отвергается, если пуста, сокращена более чем вдвое без подтверждения или старше текущей; узел продолжает со старой картой. Исправить источник и повторить синхронизацию | администратор ИБ | почта принимается по прежнему справочнику |
| Узел в плохом состоянии | слить (`DRAINING`), дождаться пустой очереди, остановить; очередь хранится в томе узла и не теряется | администратор платформы | новые письма получают временный отказ, отправитель повторит |
| Весь этап 1.1 | не переключать MX / не направлять почту на шлюз; остановить стенд и узлы; миграцию БД откатить `alembic downgrade` на предыдущую голову | администратор | боевая почта не затронута |

## 2. Откат миграции платформы

Миграция `a1c4e7b90d11` добавляет только новые таблицы транспорта и колонки; существующие таблицы
не меняются. Перед откатом сделайте резервную копию базы.

```bash
alembic downgrade -1
```

Откат удалит данные транспортных узлов, версий конфигурации, справочника и теневых копий — это записи
транспорта, а не анализа писем 1.0.x.

## 3. Если шлюз уже принял боевую почту (после ручного переключения MX организацией)

Этап этого не предусматривает, но порядок такой, чтобы ничего не потерять:

1. Вернуть MX организации на прежний адрес **вручную** (платформа DNS не меняет).
2. Слить узел; дождаться `msp_gateway_queue_messages = 0` или передать очередь вручную («Повторить доставку»).
3. Только после пустой очереди остановить узел. Ручное удаление писем из очереди — только решением человека и
   с записью в журнале аудита; автоматически письма не удаляются никогда.
4. Выключить теневой сбор; копии в журнале узла удалить по регламенту хранения.

## 4. Чего откат не делает

Не восстанавливает письма, удалённые вручную администратором; не откатывает изменения, сделанные в Exchange
вручную по сценариям `deployment/exchange/` (они только планируют и читают, порядок возврата — в
`rollback-plan.md`).
