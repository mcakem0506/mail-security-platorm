# Проверка SPF

**Относится к:** ТЗ MSP 1.2 §8, §38; RFC 7208
**Код:** `msp_antispam/auth.py` (`spf_evidence`); проверки — `tests/spam/test_spf.py`, `tests/unit/test_antispam_auth.py`

Проверку выполняет модуль SPF сканера Rspamd. MSP нормализует результат и ничего не отклоняет: `SPF_FAIL`
повышает риск (слабо, правило `ASP-003`), но письмо идёт дальше.

## Нормализация

`PASS`, `FAIL`, `SOFTFAIL`, `NEUTRAL`, `NONE`, `TEMPERROR`, `PERMERROR`. Сохраняются идентификатор проверки
(домен MAIL FROM или HELO), адрес клиента, причина и класс ошибки.

* **Пустой отправитель.** Проверка идёт по имени HELO (`identity_kind = HELO`).
* **Сбой DNS** — `TEMPERROR`, класс ошибки `DNS_TEMPORARY`, проверка в списке неполных (`SPF_TEMPERROR`). Никогда `FAIL`.
* **Источник адреса клиента** — слушатель Postfix; приватные сети по умолчанию **не** считаются «своими» (иначе
  сканер молча пропустил бы SPF для любого отправителя из частной сети): список «своих» адресов задаёт узел.

## Матрица проверок (настоящий Rspamd 3.12.1 и управляемый DNS)

pass, fail, softfail, neutral, none, temperror (SERVFAIL и тайм-аут), permerror (число DNS-запросов), `include`,
`redirect`, `a`, `mx`, `ip4`/CIDR, запись только с `ip6`, пустой отправитель; письмо с `SPF FAIL` доставляется.

## Отличие от RFC 7208 (зафиксировано)

Rspamd 3.12.1 **пропускает** синтаксически неверный механизм (`ip4:не-адрес`, неизвестный механизм) и вычисляет остаток
записи. По RFC 7208 §4.6 это `permerror`; у Rspamd получается, например, `FAIL` по заключительному `-all`. Последствие для
MSP: домен с поломанной SPF-записью получает `FAIL` вместо `PERMERROR`, и сигнал `AUTH_SPF_FAIL` для него несправедлив.
Влияние ограничено слабым весом правила, а на этапе 1.2 ничего не отклоняется. Отличие записано в реестре пробелов как
**GAP-005** ([DETECTION_GAPS.md](DETECTION_GAPS.md)) и закреплено тестами `test_deviation_*` — при смене версии сканера
тест подскажет, что поведение изменилось.
