# Проверка ARC

**Относится к:** ТЗ MSP 1.2 §11, §19, §38; RFC 8617
**Код:** `msp_antispam/auth.py` (`arc_evidence`); проверки — `tests/spam/test_arc.py`

ARC — контекст для пересылки и списков рассылки. Он **не отменяет DMARC автоматически**: письмо, у которого DMARC не
прошёл, остаётся с этим результатом, даже если цепочка ARC корректна (проверено на настоящем сканере).

## Результат

`PASS`, `FAIL`, `NONE`, `UNKNOWN` (временная ошибка DNS при проверке цепочки). Сохраняются число наборов и домены
подписантов цепочки.

## Что проверено

* корректная цепочка из одного звена → `PASS`, домен подписанта сохранён;
* нарушенная печать (подмена `d=`) → не `PASS`;
* цепочка без опубликованного ключа → не `PASS`;
* письмо без цепочки → `NONE`;
* цепочка корректна, а подпись автора нарушена списком: `ARC = PASS`, `DMARC = FAIL`.

Цепочки строит независимая реализация (dkimpy), как это делал бы список рассылки.

## Как ARC используется в MSP

Только как контекст для класса спама: при нарушенном DKIM и ARC `pass` либо при заголовках списка рассылки нарушенная
подпись считается ожидаемой и не засчитывается как признак спама ([SPAM_CLASSIFICATION.md](SPAM_CLASSIFICATION.md)). Сигнал
`AUTH_ARC_*` не влияет на риск. Доверенные звенья цепочки и «белый список» пересылающих организаций на этапе 1.2 не
ведутся.
