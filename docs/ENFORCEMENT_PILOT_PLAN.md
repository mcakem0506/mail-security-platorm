# План пилота принуждения

**Относится к:** ТЗ MSP 1.3 §17, §55, §81–§84, §90

> **MSP 1.3 IS NOT APPROVED FOR GLOBAL PRODUCTION MX CUTOVER.** Пилотный домен допускается только по отдельному плану приёмки
> (этот документ — его основа). MX переключает организация вручную; платформа DNS не меняет.

## Предусловия

1. Узлы приняли политику, дрейфа нет; аудит действий сканера чист на всех узлах.
2. Для контролей пилота есть **выборка реального потока** (рекомендуется: ≥ 1000 проанализированных писем, ≥ 200 просмотренных
   аналитиками, ≥ 100 просмотренных кандидатов на отказ; все применённые отказы и карантины просмотрены). Если объёма нет — фиксируется фактический.
3. Нет открытых инцидентов ложных срабатываний; критических ложных = 0.
4. Токены компонентов разделены ([DEPLOYMENT.md](DEPLOYMENT.md)); общий токен 1.1 отключён.
5. Описан и проверен откат MX ([GATEWAY_ROLLBACK.md](GATEWAY_ROLLBACK.md)); две независимые ноды — желательно (общая очередь запрещена, §81).

## Контроли и требуемые доказательства (§84)

| Контроль | Доказательство |
|---|---|
| `SPAM_REJECT` | реальная выборка кандидатов на отказ, доля ложных ≤ 1 %, тест отказа сканера |
| `RBL_REJECT` | просмотренный трафик со списками, одобренная лицензия, проверка утечки секретной зоны |
| `MALWARE_REJECT` | тест на безопасном артефакте и безопасное реальное свидетельство; зашифрованное ≠ вредоносное |
| `DMARC_REJECT` | **GAP-006 `RESOLVED`** и реальный трафик аутентификации; до этого — `BLOCKED_BY_GAP` |
| `PHISHING_REJECT` | только если синхронный путь отдельно утверждён |
| `QUARANTINE` | выпуск проверен; все карантинные действия просмотрены |
| Исходящее | по умолчанию наблюдение; в пилоте допустимы удержание вредоносного и временный отказ при взломе учётной записи; постоянный внешний отказ — отдельная приёмка |

## Ход пилота

Канарейка на малой области → расширение (процент/домен) → пилот на пилотном домене (повышенное согласование: второй человек с
`enforcement:pilot`) → ежедневный просмотр применённых действий → решение об остановке или расширении. Любое критическое ложное срабатывание —
пауза и инцидент. Критерии выхода — отсутствие критических ложных, ложные ≤ допустимой доли, SLO соблюдены.

## Что не входит

Глобальный перевод MX, пользовательский портал карантина, высокая доступность, SLA пропускной способности, DLP — этап MSP 1.4 и далее.
