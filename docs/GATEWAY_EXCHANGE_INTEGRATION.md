# Интеграция с Exchange

**Относится к:** ТЗ MSP 1.1 §18–§22, §47, §48, §68.26–§68.28
**Файлы:** `deployment/exchange/` (`inspect.ps1`, `plan-receive-connector.ps1`, `plan-send-connector.ps1`, `verify-connectors.ps1`, `rollback-plan.md`)
**Проверяется тестами:** `tests/unit/test_exchange_scripts.py`, `tests/gateway/test_smoke.py`, `test_tls_downstream.py`

> **MSP 1.1 IS NOT APPROVED FOR PRODUCTION MX CUTOVER.**
> Платформа ничего не меняет в Exchange сама. Сценарии либо читают, либо печатают план, который
> оператор выполняет вручную в окне изменений.

---

## 1. Принцип: сценарии не умеют менять Exchange

В пакете `deployment/exchange` нет ключа `-Apply`, и нет ни одного изменяющего командлета в исполняемом
коде. Команды `New-ReceiveConnector`, `New-SendConnector`, `Remove-*` присутствуют **только внутри текста
плана**, который сценарий печатает. Это проверяется тестом, читающим исходники: появление `New-`, `Set-`,
`Remove-`, `Add-`, `Enable-`, `Invoke-Expression` и подобного вне текста плана ломает сборку.

| Сценарий | Что делает | Меняет Exchange |
|---|---|---|
| `inspect.ps1` | собирает описание коннекторов, принимаемых доменов и ограничений в JSON-файл | нет (только `Get-*`) |
| `plan-receive-connector.ps1` | проверяет параметры и печатает команды для коннектора приёма от шлюза | нет |
| `plan-send-connector.ps1` | то же для коннектора отправки в шлюз | нет |
| `verify-connectors.ps1` | проверяет безопасность созданных коннекторов, печатает PASS/FAIL | нет (только `Get-*`) |
| `rollback-plan.md` | порядок отката | — |

Сценарии запускаются в Exchange Management Shell. Файлы сохранены с BOM, чтобы PowerShell 5.1 не испортил
не-ASCII символы.

---

## 2. Коннектор приёма (Exchange принимает почту от шлюза)

План создаёт **выделенный** коннектор, который:

* принимает SMTP **только** с адресов шлюза (`-GatewayIp`; диапазоны шире `/24` требуют явного `-AllowWideRange`,
  `0.0.0.0/0` не принимается никогда);
* привязан к собственному адресу и порту (по умолчанию `2525`), не к общим коннекторам;
* требует TLS (`-RequireTLS $true`, `-AuthMechanism Tls`);
* **не получает права релея**: `ms-Exch-SMTP-Accept-Any-Recipient` не выдаётся, поэтому Exchange не становится
  открытым релеем для внешних получателей;
* ограничен по размеру письма не меньше лимита шлюза (иначе принятое шлюзом письмо отвергнет Exchange).

`verify-connectors.ps1` проверяет это после создания: TLS обязателен, диапазоны источников — ровно шлюз, нет
диапазона «все адреса», нет права `Accept-Any-Recipient`. Код возврата: `0` — всё прошло, `1` — есть провал, `2` —
проверку выполнить не удалось.

## 3. Коннектор отправки (Exchange отдаёт почту шлюзу)

Исходящая доставка в Интернет через шлюз в MSP 1.1 **выключена по умолчанию**. План создаётся только для тестового
адресного пространства (изолированный домен, приёмник или управляемый вышестоящий сервер); адресное пространство
`*` отвергается, если не указан `-AllowWildcardAddressSpace`, и даже тогда сценарий лишь печатает план с
предупреждением. Коннектор использует шлюз как smart host с проверкой сертификата (`CertificateValidation`),
DNS-маршрутизация отключена.

---

## 4. Несколько серверов Exchange

Маршрут домена содержит упорядоченные цели. Postfix использует запасные цели как запасные MX: следующая
пробуется при любом **временном** отказе предыдущей, постоянный отказ на запасную цель не передаётся
(проверено на настоящем Postfix). Следствие — цели должны быть равноценны. Подробнее — в
[GATEWAY_MAIL_FLOW.md](GATEWAY_MAIL_FLOW.md), раздел 3.

---

## 5. Проверка связи без отправки писем

Агент шлюза проверяет каждую цель уровнями `NETWORK`, `TLS`, `SMTP`, `DELIVERY` ([GATEWAY_TLS.md](GATEWAY_TLS.md)).
Сам приём письма проверяется тестовой доставкой: письмо с тестового источника через шлюз доходит до
приёмника-двойника Exchange (`tests/gateway/test_smoke.py`). Подключение к боевому Exchange для проверки не
требуется и не предполагается.

---

## 6. Чего здесь нет

* Автоматического создания или изменения коннекторов.
* Изменения MX-записей и любых записей DNS. Переключение MX — отдельное решение организации вне этого этапа.
* Проверки на боевой почте: приёмка (`MSP_1_1_ACCEPTANCE.md`) выполнена на тестовом домене и двойниках Exchange.
