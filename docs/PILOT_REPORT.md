## 4. Качество детектирования

| Показатель | Значение | Как получено |
|---|---|---|
| Подтверждённые истинные срабатывания | | статус инцидента |
| Подтверждённые ложные срабатывания | | статус инцидента |
| Обнаруженные пропуски | | нижняя оценка, см. ниже |

> `false_negative_discovered` — **нижняя оценка**, а не recall. Учитываются только пропуски,
> которые кто-то обнаружил постфактум: по сообщению сотрудника, по инциденту, по изменению
> вердикта. Платформа не знает, чего она не видела, и выдавать эту цифру за полноту
> обнаружения нельзя.

## 8. Наблюдения по контексту

| Показатель | Значение |
|---|---|
| Чаще всего подменяемые идентичности | |
| Чаще всего встречающиеся подозрительные домены | |
| Обнаружено кампаний | |
| Расхождений со шлюзом | |
| в том числе «шлюз чисто / платформа опасно» | |
| в том числе «шлюз обнаружил / платформа нет» | |

Первый вид расхождения — штатный: письма без вложений и ссылок шлюз пропускает. Второй требует
разбора: он означает, что платформа не увидела того, что увидел антивирусный движок.

## 11. Решение

```text
[ ] READY_FOR_CONTROLLED_ROLLOUT
[ ] READY_WITH_WARNINGS
[ ] NOT_READY
```

### Обоснование

_Ссылка на конкретные цифры разделов 3–8. Решение без ссылки на измерения — мнение, а не вывод._

### Условия перехода к контролируемому развёртыванию

1. закрыты блокеры из раздела 2;
2. согласована область ящиков (`MSP_EWS_MAILBOX_SCOPE`);
3. утверждён порядок согласования действий реагирования;
4. назначены ответственные за разбор очереди.

> Успешный пилот не означает включения реагирования. Это отдельное решение с отдельными
> условиями (ТЗ 20).
