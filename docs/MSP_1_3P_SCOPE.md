# MSP 1.3P — границы пилота реального потока

**Относится к:** ТЗ MSP 1.3P §2, §5, §11, §25

> **MSP 1.3P НЕ РАЗРЕШАЕТ ГЛОБАЛЬНОЕ ПЕРЕКЛЮЧЕНИЕ PRODUCTION MX.** Сбор реальных писем начинается без изменения основного MX и Exchange.
> Этот документ — шаблон: реальные имена, адреса и ящики хранятся в **приватном эксплуатационном паспорте** организации, а не в репозитории.

Пока поле не заполнено в паспорте и не подтверждено в платформе (`POST /api/v1/pilot/attestations/scope_approved` со ссылкой на паспорт),
его состояние — `NOT_PROVIDED`, а фаза P1 закрыта.

## Что должно быть определено до первого реального письма

| Поле | Что записать в паспорте | Состояние |
|---|---|---|
| Владелец пилота | должность и ответственный (не адрес в репозитории) | `NOT_PROVIDED` |
| Почтовый администратор / ИБ / оператор / ревьюеры / владелец бизнес-риска | роли из `MAIL_ADMIN`, `SECURITY_OWNER`, `BUSINESS_OWNER` — три **разных человека** | `NOT_PROVIDED` |
| Источник реальной почты | `JOURNAL_COPY` (приоритет), `EWS_READONLY`, утверждённая копия SEG; ящик безопасности — только дополнение | `NOT_PROVIDED` |
| Пилотные ящики | 5–10 согласованных адресатов для P2; для P4 — низкокритичные адреса (не VIP, не расчётные, не юридически значимые) | `NOT_PROVIDED` |
| Срок пилота и сроки хранения | согласуются с [REAL_FLOW_PRIVACY.md](REAL_FLOW_PRIVACY.md) | `NOT_PROVIDED` |
| Основной MX, Exchange, SEG | **не изменяются**; подтверждается `production_mx_unchanged` | `NOT_VERIFIED` |
| Пилотный маршрут для P4 | отдельный поддомен или изолированная группа; отдельное согласование маршрута | `NOT_APPROVED` |

## Что в область не входит

Глобальный переход MX; массовый SMTP-отказ; пользовательский портал карантина; общая высокая доступность; управление публичным DNS;
DLP; массовое исходящее блокирование; признание продукта заменой KSMG или иного SEG.

## Состав выборки

В набор реального потока попадают письма из `JOURNAL_COPY`, `EWS_READONLY` и `GATEWAY_EVIDENCE` без заранее известного ответа.
Письма из ящика безопасности — смещённая выборка (там то, что переслали люди); файлы аналитика — импортированные; учения —
письма с заранее известным ответом. Эти три класса **не засчитываются** в реальный поток и показываются отдельно
(`GET /api/v1/pilot/metrics`, раздел `sample`). Лабораторные узлы и незарегистрированные узлы считаются лабораторными.

Пилотная группа должна давать разные паттерны: ИТ, финансы/бухгалтерия, операционная работа, внешние подрядчики и сервисные
уведомления; с вложениями, пересылками, рассылками, внутренними и внешними источниками. Копировать весь домен не нужно.

## Кто может что (RACI)

| Действие | Исполнитель | Согласование |
|---|---|---|
| Источник, охват, секреты, хранение | владелец системы, ИБ, администратор Exchange | владелец данных |
| Настройки Exchange / журнала / EWS | администратор Exchange | владелец изменения и ИБ |
| Маршруты KSMG/SEG и их свидетельства | администратор SEG | ИБ и администратор Exchange |
| Платформа, очереди, TLS, мониторинг | инженер MSP | ИБ |
| Разметка и ложные/пропущенные | аналитик ИБ | владелец детектирования |
| Решение о фазе | руководитель пилота | `MAIL_ADMIN` + `SECURITY_OWNER`; для P4 ещё `BUSINESS_OWNER` |
| Канарейка и откат | администратор MSP | второй согласующий; выключатель без задержки |

Решение о фазе вступает в силу, когда его подтвердили люди нужных ролей **каждый под своей учётной записью**; автор решение
не подтверждает, один человек не закрывает две роли ([MSP_1_3P_PILOT_RUNBOOK.md](MSP_1_3P_PILOT_RUNBOOK.md)).
