# Проверка готовности среды

**Относится к:** ТЗ 1.0.1 §4.6, §12
**Реализация:** `scripts/probe_exchange.py`, `apps/api/msp_api/services/readiness.py`

---

## 1. Назначение

Раньше перед пилотом требовалось заполнить письменную анкету: версия Exchange, адрес EWS, способ
аутентификации, топология. Анкета устаревает, заполняется по памяти и не проверяется.

Проверка задаёт те же вопросы **самой среде**: подключается с настроенными учётными данными и
сообщает, что действительно работает.

Проверка **ничего не меняет**. Возможность реагирования проверяется как право доступа и никогда
не выполняется: проверка, которая отправила бы письмо в карантин, чтобы доказать, что умеет, хуже
отсутствия проверки.

---

## 2. Запуск

```bash
docker compose exec api python scripts/probe_exchange.py
```

| Параметр | Назначение |
|---|---|
| `--json` | машиночитаемый вывод |
| `--markdown FILE` | отчёт для документа приёмки |
| `--pilot-mailbox user@corp.example` | проверить доступ к ящику пилота |
| `--section NAME` | только указанные разделы, можно повторять |

Разделы: `exchange`, `mailbox`, `directory`, `mailflow`, `addin`, `pilot`.

Код возврата: `0` для `READY` и `READY_WITH_WARNINGS`, `1` для `NOT_READY` — проверку можно
поставить шагом в CI или в регламент развёртывания.

---

## 3. Что проверяется

### Exchange / EWS

| Проверка | Блокер |
|---|---|
| способ определения endpoint (Autodiscover либо явный адрес) | нет |
| проверка TLS включена | **да** |
| разрешённые способы аутентификации | **да**, если не осталось ни одного |
| Basic-аутентификация включена | предупреждение |
| подключение и версия сервера | **да** |
| режим доступа к ящикам | нет |
| чтение MIME письма | **да** |
| чтение заголовков | **да** |
| чтение вложений | предупреждение |
| поиск по ящикам | предупреждение |
| возможность реагирования | см. ниже |
| доступ к ящику пилота | **да**, если указан и недоступен |

EWS, который не настроен, даёт `ПРОП`, а не ошибку: платформа работает через security mailbox и
надстройку Outlook — это поддерживаемая конфигурация.

Версия Exchange сообщается, но **в логике адаптера не используется**: 2016 и 2019 для модуля
равнозначны, возможности проверяются запросами к живому серверу.

### Security mailbox

Подключение, выбор папки, наличие папок `Processed` и `Failed` (создаются автоматически при
первом использовании).

### Active Directory

LDAPS или StartTLS — **блокер**, если ни того ни другого: пароли пользователей передавались бы
открытым текстом. Отключённая проверка сертификата контроллера домена — тоже блокер.

Дополнительно: подключение, base DN из RootDSE, сопоставление групп и ролей.

### Почтовый поток и шлюзы

Настроенные шлюзы, их состояние, количество доверенных узлов, объявленные `authserv-id`,
внутренние сети. Подробно — [`TRUSTED_MAIL_FLOW.md`](TRUSTED_MAIL_FLOW.md).

Шлюз без доверенных узлов даёт предупреждение: его заголовки будут показываться и не будут
учитываться.

### Надстройка Outlook

Базовый адрес платформы должен быть задан и использовать HTTPS — **блокер**: Outlook загружает
надстройку только по HTTPS. Плюс замечания о доверии к сертификату на клиентских машинах.

### Режим пилота

Реагирование должно быть отключено либо работать только в dry-run — иначе **блокер**: теневой
пилот запрещает изменение почты (ТЗ 1.0.1 §8).

---

## 4. Решение

```text
READY                 проверено, блокеров и замечаний нет
READY_WITH_WARNINGS   пилот можно начинать; перечисленные замечания открыты
NOT_READY             есть блокеры
```

`READY_WITH_WARNINGS` — **не мягкий пропуск**. Он означает: теневой пилот начинать можно, и
перечисленные пункты должны быть закрыты до контролируемого развёртывания. Каждое замечание
названо явно.

## 6. Отчёт для приёмки

```bash
docker compose exec api python scripts/probe_exchange.py \
  --markdown /tmp/readiness.md --pilot-mailbox pilot1@corp.example
docker compose cp api:/tmp/readiness.md ./docs/readiness-$(date +%F).md
```

Markdown-отчёт содержит решение, блокеры, замечания и таблицу всех проверок — его можно
приложить к [`MSP_1_0_1_ACCEPTANCE.md`](MSP_1_0_1_ACCEPTANCE.md) как есть.

## 7. Разбор типичных результатов

| Сообщение | Что делать |
|---|---|
| `EWS не настроен` | Не ошибка. Платформа работает через security mailbox. Настраивайте EWS, только если нужен поиск по ящикам или реагирование |
| `Разрешённые способы аутентификации — ни одного` | В `MSP_EWS_AUTH_PREFERENCE` остался только Basic, а он отключён. Добавьте Kerberos/NTLM либо включите Basic осознанно |
| `Basic-аутентификация включена` | Пароль сервисной учётной записи уходит при каждом запросе. Допустимо только при невозможности иного и после отдельного согласования |
| `Чтение MIME письма — недоступно` | Учётной записи не хватает прав на ящик. Проверьте делегирование или impersonation |
| `Реагирование включено без явной области` | Задайте `MSP_EWS_MAILBOX_SCOPE`. Без области развёртывание могло бы затронуть любой ящик |
| `LDAP без TLS` | Включите `MSP_AD_USE_SSL` или `MSP_AD_START_TLS` |
| `Проверка сертификата отключена` | Без внутреннего CA экспортируйте сертификат контроллера домена и укажите `MSP_AD_CA_FILE`. Отключать проверку нельзя: по этому каналу идут пароли |
| `Шлюз настроен, но ни один узел не описан` | См. [`TRUSTED_MAIL_FLOW.md`](TRUSTED_MAIL_FLOW.md) §5 |
| `Базовый адрес платформы: HTTP` | Outlook загружает надстройку только по HTTPS |

---

## 8. Когда запускать

1. **До пилота** — получить решение и закрыть блокеры.
2. **После изменения конфигурации** — Exchange, AD, шлюзов, топологии.
3. **Регулярно во время пилота** — срок сертификата, изменившаяся маршрутизация и отключённая
   возможность обнаруживаются проверкой, а не отсутствием обнаружений.
4. **Перед контролируемым развёртыванием** — решение должно стать `READY` либо
   `READY_WITH_WARNINGS` с явно принятыми замечаниями.
