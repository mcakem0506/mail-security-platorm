# Готовность контролей и пробелы

**Относится к:** ТЗ MSP 1.3 §4–§8, §24–§30, §45, §46, §83, §84
**Код:** `msp_enforcement/readiness.py`, `apps/api/msp_api/services/enforcement.py`

Готовность считается **отдельно для каждого контроля** и пересчитывается при каждом просмотре, запросе и согласовании.
Состояния: `READY`, `READY_WITH_WARNINGS`, `NOT_READY`, `BLOCKED_BY_GAP`.

## Блокировка пробелами

| Пробел | Действие |
|---|---|
| GAP-006 (DMARC по RFC 9989) | `DMARC_REJECT` = `BLOCKED_BY_GAP`, пока пробел не `RESOLVED`. Активация — 409 и событие аудита. Нет записи о пробеле — считается открытым |
| GAP-005 (SPF permerror) | SPF остаётся свидетельством: коды `AUTH_SPF_*` **не могут быть единственным основанием** отказа; `permerror` как основание запрещён. Остальные причины должны присутствовать |

Проверка стоит в двух местах: при активации в панели и **в движке на узле при каждом решении** (по снимку пробелов, подписанному
вместе с политикой). Даже если запись в базе подделана и запрос на включение «одобрен», узел решения не применит.
Закрытие пробела — отдельная работа с проверкой ([DETECTION_GAPS.md](DETECTION_GAPS.md)); статус `RESOLVED` из-за наличия кода запрещён.

## Условия по контролям

| Контроль | Условия готовности |
|---|---|
| все | аудит действий сканера чист на **всех** узлах (нет отчёта = не подтверждено); пороги версионируются; тесты контроля подтверждены ссылкой на ревизию; нет незакрытого инцидента |
| `SPAM_REJECT` | выборка просмотренных кандидатов на отказ ≥ 100 (настраивается), доля ложных ≤ 1 %, нет критических ложных, нет системной проблемы, тест отказа сканера пройден |
| `RBL_REJECT` | выборка как у спама; лицензия одобрена и провайдер включён; провайдер исправен; утечка секрета в ответ/журнал проверена |
| `MALWARE_REJECT` | выборка; только высокая уверенность; семантика тайм-аута проверена. Зашифрованное и неподдерживаемое — не вредоносное |
| `PHISHING_REJECT` | синхронный путь отдельно утверждён |
| `QUARANTINE` | ключ шифрования настроен; выпуск проверен (хотя бы одно выпущенное письмо доставлено) |
| `OUTBOUND_BLOCK` | отдельная приёмка исходящего принуждения |

Нет знаменателя — доли `null`, не 0. Верхняя граница доверительного интервала Вильсона показывается и даёт предупреждение
`FP_UPPER_BOUND_ABOVE_THRESHOLD`, если выборка мала для уверенности.

## Лабораторная и реальная выборка (§83)

Выборка с узлов роли `LAB` — лабораторная: при `MSP_ENFORCEMENT_LAB_MODE=true` она допускает **только канарейку** и даёт
`READY_WITH_WARNINGS` (`LAB_EVIDENCE_ONLY`); пилот и любая готовность без лабораторного режима требуют выборки реального потока.
Синтетическая приёмка заканчивается решением `READY_WITH_WARNINGS`.

## Подтверждения

Проверки, которые нельзя вывести из базы (тесты зелёные, отказоустойчивость, утечка секрета, семантика тайм-аута), даются
подтверждением `POST /enforcement/controls/{id}/attest` с **обязательной ссылкой на ревизию или отчёт**; подтверждение пишет, кто и
когда его дал. Права — те же, что у канарейки; всё в аудите.
