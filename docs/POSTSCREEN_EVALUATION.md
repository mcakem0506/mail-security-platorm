# Оценка postscreen, greylisting и проверок до приветствия

**Относится к:** ТЗ MSP 1.2 §21
**Статус:** оценка и профиль конфигурации. **На этапе 1.2 блокирующий postscreen не включается.**

## Что включено и что нет

| Возможность | Состояние в 1.2 |
|---|---|
| Greylisting (Rspamd) | реализовано как возможность, **выключено по умолчанию**; с этапа 1.3 выпуск конфигурации с включённым greylisting **блокируется аудитом итоговых действий сканера** (`GREYLIST`) до отдельного решения о канарейке ([ENFORCEMENT_ARCHITECTURE.md](ENFORCEMENT_ARCHITECTURE.md)) |
| Метрики greylisting «в тени» | есть: действие `greylist` считается как предложение (`msp_rspamd_suggested_actions_total{action="greylist"}`), письмо не откладывается |
| Postscreen (Postfix) | не включён: параметры `postscreen_*` не входят в белый список конфигурации узла, и пакет с ними отвергается |
| DNSBL до приветствия | только оценка профиля, ниже; в работе не используется |

Проверка отказа: `tests/unit/test_gateway_milter.py::TestPostscreenIsNotAvailable` — узел отвергает параметры `postscreen_*`
в `main.cf` и службу postscreen в `master.cf` (они вне белого списка `bundle.MAIN_CF_PARAMETERS`), отрисованная
конфигурация их не содержит, а у спецификации шлюза нет поля, которое их включало бы.

## Профиль для оценки (не применяется)

Для лабораторного сравнения администратор может вручную применить на изолированном стенде:

```ini
# ТОЛЬКО ОЦЕНКА. Не применять на узле, принимающем почту организации.
postscreen_access_list = permit_mynetworks
postscreen_greet_action = enforce        # поведение «в тени» — ignore
postscreen_dnsbl_sites = lab.rbl.test*2  # лабораторная зона стенда, не публичный список
postscreen_dnsbl_action = ignore         # в оценке: только журнал, без отказов
postscreen_dnsbl_threshold = 2
postscreen_greet_wait = 6s
```

Критерии оценки: доля легитимных отправителей, которых postscreen *задержал бы* (по журналу при `ignore`); задержка
первого письма новых легитимных источников при greylisting; число писем, не вернувшихся после временного отказа. Решение о
включении принимается отдельным этапом (1.3) по измеренным данным, а не по этому документу.

## Симулятор политики для greylisting

Кандидат политики с `greylisting_enabled = true` может быть оценён симулятором ([SPAM_POLICY_SIMULATOR.md](SPAM_POLICY_SIMULATOR.md)):
он покажет, для какой доли уже принятых писем сканер предложил бы `greylist`, не откладывая ни одного.

## Почему это не включено сейчас

Временный отказ незнакомому отправителю (greylisting, postscreen) замедляет легитимную почту и для первых писем срывает
сроки; на этапе, где ложные срабатывания ещё не измерены на реальном потоке, это недопустимо. Условие пересмотра —
`reject_safety` ([SPAM_REAL_FLOW_VALIDATION.md](SPAM_REAL_FLOW_VALIDATION.md)) и отдельная приёмка этапа 1.3.
