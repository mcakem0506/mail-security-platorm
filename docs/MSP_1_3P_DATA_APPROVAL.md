# MSP 1.3P — допуск к обработке реальной переписки

**Относится к:** ТЗ MSP 1.3P §5, §9, §27

Шаблон. Решение о допуске принимает организация; платформа его не подменяет и не проверяет по существу — она фиксирует **ссылку**
на документ допуска и отказывается переходить к сбору, пока ссылки нет. Реальные документы, имена и адреса в репозиторий не кладутся.

## Что должно быть утверждено до P2

- [ ] Правомерность доступа к корпоративной переписке и персональным данным; границы использования результатов.
- [ ] Согласование ИТ и ИБ; при необходимости юридической и кадровой функций.
- [ ] Информационное уведомление выбранных работников по внутренним правилам.
- [ ] Срок хранения исходных писем и обезличенных метрик: [REAL_FLOW_PRIVACY.md](REAL_FLOW_PRIVACY.md) (по умолчанию исходные 14 дней, обезличенные 365).
- [ ] Запрет внешней передачи полного содержимого; порядок выгрузки только агрегатов (`GET /api/v1/pilot/evidence`).
- [ ] Порядок отзыва доступа: кто, как быстро, как подтверждается удаление.
- [ ] Письма поступают **только** из среды, на работу с которой организация дала разрешение; персональные ящики вне контура не используются.
- [ ] Права служебной учётной записи Exchange ограничены согласованными ящиками (выгрузка прав приложена).

## Как это отражается в платформе

| Условие | Что делает платформа |
|---|---|
| Нет подтверждения `data_approval` / `scope_approved` | решение о входе в P1 отклоняется (409), гейт показывает недостающее |
| `MSP_REAL_FLOW_SHADOW` не включён | приём журнального отчёта отклоняется (409) |
| Не задана `MSP_REAL_FLOW_FINGERPRINT_SALT` (≥ 16 символов) | приём отклоняется (409): без соли отпечаток воспроизводим любым человеком, а смена соли разорвала бы дедупликацию |
| Сотрудники пилотной группы | уведомления и реагирование в теневом режиме выключены принудительно |
| Выгрузка доказательств | только агрегаты, критерии и решения; без тел писем, тем, адресов получателей и адресов участников решений |
| Каждый приём, подтверждение, решение, остановка и выгрузка | запись в аудит; адресов и содержимого в записи нет |

## Подтверждение

Подтверждение записывает уполномоченный человек: `POST /api/v1/pilot/attestations/data_approval` со `status=PASS` и `evidence_ref` — ссылкой на
документ в утверждённом хранилище. Пустая ссылка отклоняется: «проверено» без документа равносильно «не проверено».

```text
DATA_APPROVAL_REF:        NOT_PROVIDED
APPROVER (роль, не адрес): NOT_PROVIDED
DATE_UTC:                 NOT_PROVIDED
```
